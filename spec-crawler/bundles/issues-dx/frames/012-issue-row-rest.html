W1 · Route the canvas hover-preview through the pair-wired FullParamRow

Problem

The canvas hover-card (components/editor/framer/generic-param-renderer.tsx:539) calls FullParamRow without the pair / decorators / sub-collection props. The modern Pair* dispatch (getPairRendererKey) only fires when pair is supplied, so on the canvas the golden renderer drops to the legacy getParamUIType switch, and table / chart / matrix / standard-matrix / editable-label / combobox / discreet-info / group-box all render as plain "Not Initialized" text.

Fix

Mirror what dataminer-element-content.tsx does:

  • Build pairIndices once via buildPairDetectionIndices(protocolParams, treeControls) at the canvas container level (canvas-view-container.tsx), plus a pairFor callback and a decoratorsFor callback fed by the decorator sub-table reads (paramDiscreets, paramInterpreteExceptions, paramColumnOptions, paramMatrixMappings, paramParametersViewParameters).

  • Thread pair, decorators, columnOptions, matrixMappings, chartParameters, discreetsByParam, tableColumnOptions down to the FullParamRow call at generic-param-renderer.tsx:539.

Perf guard (mandatory)

The canvas cell renderer is virtualized and runs per row. Do NOT call buildPairDetectionIndices or read the decorator tables per cell. Compute them once in the container, memoized with a content signature, and pass memoized pairFor/decoratorsFor closures (see feedback_container_presentation_split, feedback_zero_array_structural_memo).

Acceptance

  • A positioned table/chart/matrix/editable-label/combobox param shows its real widget in the canvas Play-hover preview.

  • Canvas scroll FPS unchanged (no per-cell index rebuild).

  • pnpm tsc --noEmit no new errors.

Reference: feedback_preview_pair_aware_renderer, docs https://docs.dataminer.services/develop/devguide/Connector/UIComponentsVisualization.html
